# Проверка позиций перед публикацией

18 октября 2026. Серверный source journal уже работает; Holdings ещё не публикуются.

## Реальные образцы

Дополнение после получения третьего XML 18 октября: снимок на 30 июня получен. Проверка `check_ibkr_positions.py` с полным июльским отчётом подтвердила равенство начальных количеств плюс 3 STK-исполнения конечным количествам на 31 июля по 7 инструментам, без расхождений. Проверены совпадение счёта, поддержанные типы позиций/исполнений, валюты и множители. Значения и идентификаторы не выводились и не добавлялись в Git. Это свидетельство сверки количества за июль, не подтверждение всей истории или готовности серверной публикации.

Короткий отчёт 10–22 июля относительно 30 июня отклонён с `EVENT_COVERAGE_GAP`, поскольку не покрывает 1–9 июля. Для этой проверки нужен уже имеющийся полный июльский отчёт; повторная выгрузка не требуется. Следующее описание отсутствующего снимка сохраняет историю первоначального исследования.

В двух полученных Activity Flex XML есть OpenPositions: по 7 STK/SUMMARY записей на 22 и 31 июля 2026. Присутствуют accountId, conid, currency, multiplier, reportDate, position, side, levelOfDetail, code. В этих образцах позиции Long, multiplier 1. Количества совпадают; между датами нет STK-сделок. SecuritiesInfo содержит идентификаторы инструментов. Начального снимка на 30 июня нет. openPrice/costBasisPrice не являются начальным количеством.

Проверка воспроизводится локально, без отправки или копирования XML в репозиторий:

```powershell
python -B scripts/check_ibkr_positions.py 'path/to/july-22.xml' 'path/to/july-31.xml'
python -B -m unittest discover -s tests -p 'test_ibkr_positions.py'
```

Диагностика использует Decimal и выводит только даты и счётчики. Это отдельный ограниченный инструмент для выбранных снимков, не замена серверной валидации XML. Синтетические тесты покупок, дробных количеств и полного закрытия не означают, что эти случаи подтверждены реальными отчётами. Для пары 22–31 июля результат: 7 инструментов, 0 STK-исполнений, 0 расхождений; fullHistoryVerified остаётся false.

## Ранее недостающий файл — получен

Activity Flex XML за 30 июня 2026 либо весь июнь с конечной датой 30 июня, с тем же набором секций и без фильтров инструментов. Нужны конечные Open Positions. Уже полученные июльские отчёты повторять не требуется. Проверка фактически доступного архивного периода остаётся отдельной задачей: наличие двух июльских файлов не доказывает доступность всей истории.

## Следующий этап после получения

1. Проверить счёт, даты снимков, покрытие июля и неизменность идентификаторов/валют/множителей. Для каждого conid сверить количество на 30 июня плюс подписанные июльские исполнения с количеством на 31 июля точной арифметикой. Отсутствие инструмента в полном конечном снимке трактовать как ноль только после проверки полноты секции.
2. Блокировать публикацию при пробелах, исправлениях, неподдержанных корпоративных действиях, переводах активов, неоднозначных IDs или несовпадении количества. Не восстанавливать «проверенное» начало обратным вычислением из конца.
3. Спроектировать owner-scoped хранение версии проверенного снимка, привязанной к исходному отчёту и ревизии журнала. Повтор и overlap не должны суммировать снимки. Публиковать согласованную дату позиций и cash; исходные валюты сохранять раздельно.
4. В preview показать дату, покрытие и причины блокировки; Holdings публиковать только после серверной повторной проверки и явного подтверждения. При новой ревизии повторить сверку. RLS и доступ через owner-checked RPC сохранить.
5. Проверить независимую начальную позицию, покупку, продажу/закрытие, дробные количества, overlap, stale и чужого владельца. Реальные и синтетические доказательства отмечать отдельно. До достаточной истории и согласованной методики доходность не рассчитывать.

Схема, API и UI пока не изменены. Подключение Flex Web Service и ежедневная синхронизация — дальнейший этап.

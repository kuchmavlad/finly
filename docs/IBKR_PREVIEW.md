# Локальный предпросмотр IBKR

Реализован 16 октября 2026. Открыть **Settings → Preview IBKR reports** после входа.

1. Choose Activity Flex XML: выбрать месячный отчёт.
2. Проверить период, маскированный счёт, состав секций, записи и сверку cash по каждой валюте.
3. Compare another XML: выбрать отчёт за вложенный период. Сравнение всегда с первым файлом, не с предыдущим сравнением и не с базой Finly.
4. `new` — ID отсутствует в первом файле; `unchanged` — ID и атрибуты совпадают; `changed` — тот же ID с другими атрибутами; `ambiguous` — отсутствующий/повторный ID или неподдержанная запись. Исчезновение строки не означает отмену.
5. Clear reports очищает память экрана и отменяет разбор. Уход со страницы/выход из аккаунта удаляет состояние. Новый пользователь не получает предыдущий preview.

Основной учёт не меняется: нет загрузки на сервер, записи пакета, Apply, расписания или токена брокера. Сверка относится к полному текущему отчёту, включая совпадающие строки: она не рассчитывается только по `new`. Начальные позиции и полная история с открытия не проверяются; доходность не вычисляется.

## Границы адаптера

Основан на реально проверенных XML, см. IBKR_SAMPLE_FINDINGS.md. Читает один Activity Flex account и ожидает секции согласованного шаблона. Суммы/количества сохраняются строками; арифметика — bigint с 18 десятичными разрядами. Вход ограничен 18 целыми и 18 дробными разрядами, превышения отклоняются без округления. Не складывает BASE_SUMMARY, Sec/Com и исходные валютные строки повторно.

Первый mapping: STK executions с multiplier 1 и комиссией в валюте сделки; CASH/AFx с двумя валютными сторонами; cash Deposits/Withdrawals с transactionID; входящий INTERNAL CASH transfer с cashTransfer. Неизвестные коды, исправления, облигации, исходящие/иные переводы, выплаты/налоги и непустые неподдержанные секции помечаются проблемами. Возможность разобрать BUY/SELL и знаки денежной суммы не означает проверку всех сценариев реальными образцами.

Для неподдержанных/неоднозначных строк финансовые итоги частичные и явно не подтверждены. Равенство cash само по себе не разрешает будущую запись в ledger. Сравнение строгое: сохраняет все атрибуты, изменение представления даже эквивалентной суммы направляется на review. Идентификаторы пока только локальные в рамках одного account и вида записи; серверная owner-scoped идентичность будет отдельным этапом.

XML: saxes 6.0.0, строгая грамматика, запрет DTD/ENTITY, processing instructions, namespaces/XInclude, CDATA и значимого текста; лимиты 10 MiB, 20 000 узлов, глубина 8, 160 атрибутов/узел и 4096 символов/значение. Разбор по блокам 16 KiB с yield, отменой и лимитом 30 секунд; финальная нормализация ограничена числом узлов. Это более строгий лимит первой мобильной версии, чем предложение в общем плане. Детали записей показываются страницами по 25, ошибки — первые 30 с указанием остатка.

Saxes выбран как строгий потоковый JS-парсер без сетевого резолвера и native-кода; upstream архивирован, версия закреплена. Перед серверным импортом повторно оценить поддержку/безопасность зависимости. npm audit: 29 замечаний в полном дереве (10 moderate, 19 high), без записей для saxes/xmlchars/expo-document-picker/expo-file-system; force-upgrade не применялся.

## Локальные файлы и проверки

DocumentPicker/FileSystem установлены через expo install по SDK 57. На native читается временная cache-копия, удаляемая в finally; оригинал не удаляется. При аварийном завершении ОС до finally копия может остаться в cache. На web используется File.text(), временный blob URL освобождается. Отчёты не сохраняются в SecureStore/AsyncStorage и не попадают в логи. Пользовательские XML не хранить в Git.

Unit-тесты содержат только явно синтетические fixtures. Проверка реальных локальных образцов без вывода финансовых значений/ID:

```powershell
node --experimental-strip-types scripts/check-ibkr-samples.ts '<путь к месячному XML>' '<путь к пересекающемуся XML>'
```

На предоставленной обновлённой паре: оба отчёта без validation issues, cash сходится точно во всех исходных валютах, все записи короткого периода unchanged. Это проверка доменного кода, не взаимодействия с Files на iPhone.

TypeScript, lint, 48 тестов, web export и iOS/Hermes export прошли. Первый iOS export упёрся в запрет записи временного hbc в sandbox; повтор с разрешением завершился успешно. Ручной сценарий на устройстве пока не подтверждён.

Проверить на iPhone: выбор XML из Files, отмену picker/разбора, повтор того же файла, сравнение двух периодов, Clear, возврат на экран, выход/смену пользователя, длинные суммы и VoiceOver. Установленный Expo Go должен включать SDK 57 DocumentPicker/FileSystem; отдельные ios/android каталоги вручную не создавать.

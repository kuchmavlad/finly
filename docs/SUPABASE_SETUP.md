# Supabase: серверный пилот Finly

Обновлено: 15 октября 2026. Проект: `jntgwwcgyzhgjhatozld`, регион eu-west-1.

## Текущее подключение

Основной интерфейс работает с серверными портфелями и денежными операциями. Overview показывает записанные остатки по исходным валютам; Activity — пополнения/выводы страницами по 50. Выбор портфеля общий для вкладок, включая All portfolios. Создание — из выбора портфеля, пустого состояния или Settings → Manage portfolios. Запись денег — через Record cash movement.

Holdings и Analytics пока показывают объяснения отсутствующих функций. Нет реального брокера, котировок, FX, сделок или инвестиционной доходности. Demo-репозиторий не подключён к приложению.

## Миграции

В облаке через Supabase MCP применены:

- `20261015065115_pilot.sql`: таблицы, RLS, запись портфелей/денег, аудит, приватный bucket.
- `20261015165100_server_portfolios.sql`: остатки по всей истории и курсорная история, индексы для чтения. Локальная версия синхронизирована с историей облака.

Для существующего проекта повторно применять SQL не нужно. Для новой среды применить обе миграции по порядку.

`cash_balances(p_portfolio_id uuid = null)` возвращает строки `currency, amount`. `amount` — текст PostgreSQL numeric, SUM по всей истории. null означает все собственные портфели; разные валюты не складываются.

`cash_entries_page(p_portfolio_id, p_kind, p_before_date, p_before_created_at, p_before_id)` возвращает до 50 записей с amount как text. Параметры по умолчанию null; курсор передаётся целиком по последней записи. Сортировка — occurred_on, created_at, id по убыванию. p_kind — deposit, withdrawal или null. Старый list_cash_entries остаётся для совместимости.

Новые RPC имеют фиксированный search_path, проверяют auth.uid() и владельца выбранного портфеля. SECURITY DEFINER нужен для чтения numeric без выдачи клиенту прямого доступа к amount. EXECUTE доступен только authenticated, прямые записи запрещены. Существующие write RPC и RLS не изменены.

## Настройка и вход

`.env.local` содержит только публичные EXPO_PUBLIC_SUPABASE_URL и EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY, исключён из Git. Пароли, токены и серверные ключи в репозиторий не добавлять.

Email/password, регистрация и подтверждение email включены. Пользователь подтвердил, что цикл регистрации и входа работает. Google-вход отменён. Sign out находится внизу Settings.

Site URL: https://kuchmavlad.github.io/finly/ . GitHub Pages публикуется из отдельной ветки codex/auth-pages; копия страницы — web/auth/index.html. Изменение копии само по себе не обновляет опубликованную страницу.

Стандартная почта Supabase ограничена. Собственный SMTP и восстановление пароля остаются задачами перед публичным запуском. Настройки почты, тариф и реальные брокерские счета в этой задаче не менялись.

## Надёжность

- Суммы остаются строками на всём пути, до 18 знаков дробной части. Нет конвертации через Number или округления до minor units.
- Сервер запрещает вывод сверх записанного остатка, включая нарушение последующих дневных остатков задней датой; внутридневной порядок не моделируется.
- Перед отправкой pending-запрос сохраняется через существующий deviceStorage. Ключ содержит проект и user ID; старый формат pending поддерживается.
- Неопределённый ответ, ошибка сохранения/очистки SecureStore или перезапуск сохраняют тот же UUID и payload. Новая денежная операция недоступна до разрешения pending. Повтор идемпотентен.
- Подтверждённый отказ валидации разрешает исправить ввод. Повреждённый pending или ошибка его чтения блокируют запись; UI предлагает повтор восстановления.
- Ошибка обновления после успешной записи показывается отдельно и не превращает сохранение в неуспех. Ошибка загрузки не отображается как нулевой остаток.
- При выходе/смене пользователя общий store удаляется; запоздалые ответы игнорируются. Pending остаётся под ключом прежнего пользователя для безопасного восстановления при его следующем входе.
- Native-сессия и pending используют SecureStore; web-превью хранит их только в памяти. Переустановка приложения не гарантирует сохранность pending.

## Фактические проверки

15 октября: TypeScript, lint, 35 тестов (включая PGlite) и iOS export прошли. Hermes export выполнялся вне песочницы из-за запрета записи временного bytecode-файла.

SQL-тесты проверяют историю свыше 100 записей, точные дроби, несколько валют/портфелей, курсор с одинаковыми датами/временем, фильтры, RLS и запреты прямых записей. Тесты store проверяют двойное нажатие, потерю ответа, восстановление после создания нового store, ошибки хранилища, смену пользователя, запоздалую страницу и ошибку refresh после успешной записи.

Облачная проверка новых RPC выполнена транзакцией с временными тестовыми пользователями, SET ROLE и JWT subject claims; проверены точная сумма, повтор записи, отказ overspend, изоляция и запрет anon. Транзакция отменена, тестовых пользователей и операций не оставлено. Это проверка SQL, а не двух настоящих Auth-сессий через REST.

Не выполнены в этом запуске: облачный end-to-end с двумя настоящими Auth-сессиями, перезапуск/выход на iPhone, клавиатура и VoiceOver. Учётных данных тестовых пользователей нет; iPhone недоступен агенту. После ошибки подключения к старому порту запущен свежий web-сервер; экран входа подтверждён в браузере, защищённые экраны без сессии не проверены. Сценарии — DEVICE_CHECKLIST.md.

Security Advisor: ожидаемый INFO об отсутствии политик у закрытого cash_entry_audit и WARN для пяти намеренно открытых authenticated SECURITY DEFINER RPC. [Описание RPC-предупреждения](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable). Также обнаружено отключение leaked password protection; настройка не менялась. [Описание защиты паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## Ограничения и дальнейшие этапы

Финансовые записи неизменяемы через клиент. Переводы между портфелями, исправления, сделки, налоги, комиссии, FX, XIRR/TWR и реальный IBKR требуют отдельных согласованных моделей. Не адаптировать настоящие сделки к demo-типам.

На Free не рассчитывать на включённые автоматические backups. Перед импортом реальных отчётов нужен защищённый экспорт базы/Storage вне Git и проверка восстановления. Bucket ibkr-reports остаётся приватным, загрузка клиентом запрещена. Платные сервисы не подключались.
